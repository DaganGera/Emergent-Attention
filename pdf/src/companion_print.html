Chapter 1 · Part I

Numbers as Vectors, Images as Grids of Numbers

Intuition

A vector is nothing more than an ordered list of numbers. "3 kilometers east, 4 kilometers north" is a vector: two numbers, in a fixed order, describing one thing (a position). A single pixel's color, "red=200, green=40, blue=40," is also a vector — three numbers, in a fixed order, describing one thing (a color). Everything a neural network computes with — an image, a word, a hidden layer's output — is stored as a vector or a grid of vectors. There is no deeper trick here: "the network's internal representation" always just means "a list of numbers."

Formally, a vector of length D is written v ∈ ℝD, meaning an ordered tuple of D real numbers, v = (v1, v2, …, vD). D is called the vector's dimension. In this project, every image patch is eventually represented as a vector of dimension D = 192 — not because 192 is special, but because it's the width the network's designer chose for its internal "channel" dimension (Appendix A of the paper).

The dot product

The single most common operation on two vectors of the same length is the dot product: multiply each pair of matching entries, then add up all the products.

a · b = a1b1 + a2b2 + … + aDbD = Σi aibi
Worked Example — dot product

Let a = (2, 0, −1) and b = (3, 4, 5).

a · b = 6 + 0 − 5 = 1. That's the whole procedure — multiply pairwise, then sum. You will see this exact operation dozens of times later: it's the arithmetic core of attention (Chapter 15), of every "Linear" layer (Chapter 2), and of measuring how similar two feature vectors are (Chapter 34).

Key Insight

A dot product is a single number that measures how much two vectors "point the same way." Two vectors pointing in similar directions produce a large positive dot product; opposite directions produce a large negative one; unrelated (perpendicular) directions produce something close to zero. This one fact is the entire basis of the attention mechanism in Chapter 15 and the drift metric in Chapter 34.

Images as grids of vectors

A grayscale image is a 2-D grid of numbers — one brightness value per pixel. A color image adds a third axis for the red/green/blue channels, so it's stored as a tensor (a multi-dimensional grid of numbers) of shape H×W×C: height, width, and channel count (C=3 for RGB).

Chapter 14 covers exactly how that conversion happens; for now, the important fact is just: an image becomes a grid of vectors, one vector per patch, and everything downstream operates on that grid.

Two numbers you will see constantly from here on: n = 196 (the number of patches / tokens per image) and D = 192 (the length of the vector describing each patch). Every formula in Chapter 15 onward that mentions "the cost is O(n2D)" is really just talking about combinations of these two numbers.

Chapter 2 · Part I

Matrices and Matrix Multiplication

Intuition

A matrix is a rectangular table of numbers — rows and columns. If a vector is one list of numbers, a matrix is a list of lists. The single most important thing a matrix does in this entire project is act as a "recipe" for turning one vector into another vector, usually of a different length — that recipe is called a linear layer, and it is the single most common building block in every network described in this book.

A matrix with R rows and C columns is written W ∈ ℝR×C. Multiplying a matrix by a vector, y = Wx, produces a new vector y whose i-th entry is the dot product of W's i-th row with x:

yi = Σj Wij xj
Worked Example — a linear layer by hand

Take a tiny "linear layer" that turns a 2-dimensional input into a 3-dimensional output: x = (1, 2), and a weight matrix

col 1col 2
row 120
row 211
row 3−13

Row 1 · x = 2×1 + 0×2 = 2. Row 2 · x = 1×1 + 1×2 = 3. Row 3 · x = −1×1 + 3×2 = 5. So y = Wx = (2, 3, 5). A 2-dimensional vector became a 3-dimensional vector, using nothing but nine numbers (the matrix) and repeated dot products.

Real layers add one more piece, a bias vector b, so the full operation is y = Wx + b. If b = (0.5, 0.5, 0.5) here, y becomes (2.5, 3.5, 5.5).

Key Insight

Every time this book (or the paper) says "Linear," "projection," "W1·perc + b1," or draws an arrow labeled with a weight matrix, it means exactly the procedure above: multiply, sum, add a bias. A model's "weights" — the things training actually changes — are just the numbers inside these matrices (and a handful of biases). "Training a 6.46-million-parameter model" literally means: there are 6.46 million individual numbers, spread across many such matrices, and training is the process of adjusting all of them.

Matrices can also multiply each other, not just a vector: if A is R×K and B is K×C, their product AB is R×C, computed by taking the dot product of each row of A with each column of B. This is exactly how a whole batch of vectors gets processed at once — stack many input vectors as rows of a matrix, multiply by the weight matrix once, and every row of the output is that row's transformed vector. This is why GPUs are fast for neural networks: matrix multiplication is one operation that processes thousands of vectors in parallel.

Chapter 3 · Part I

Slopes, Derivatives, and Gradients

Intuition

A derivative answers one question: "if I nudge this number up slightly, does the output go up or down, and by roughly how much?" That's it — a derivative is a slope. Training a neural network is, at its core, nothing but repeatedly asking this question for every one of its millions of weights and nudging each one in the direction that makes the network's error go down.

For a function f(x), the derivative at a point x is written f′(x) or df/dx, and it is the slope of the curve at that exact point — formally, the limit of (f(x+h) − f(x)) / h as the step size h shrinks to zero. You do not need the limit machinery for this book; you need the handful of rules it produces and the ability to read what a derivative is telling you.

Worked Example — the slope of f(x) = x2

The rule for this shape is f′(x) = 2x. At x=3: f(3)=9 and f′(3)=6, meaning near x=3, nudging x up by a small amount increases f at roughly 6× that rate. Check it directly: f(3.1) = 9.61, and 9 + 6×0.1 = 9.6 — matches almost exactly. At x=0, the slope is 2×0=0: the bottom of the bowl is flat, which is exactly where you'd stop if you were rolling downhill — the idea Chapter 9 turns into an actual training algorithm.

Many variables at once: the gradient

A neural network's error is not a function of one number, it's a function of every one of its millions of weights simultaneously. The generalization of "slope" to many variables is the gradient: a vector containing the partial derivative with respect to each variable separately (holding all the others fixed). Written ∇f, it points in the direction that increases f the fastest.

Worked Example — a gradient in two variables

Let f(w1, w2) = w12 + w22. Treating w2 as a constant, ∂f/∂w1 = 2w1; symmetrically ∂f/∂w2 = 2w2. At (w1,w2) = (1, 2): the gradient is ∇f = (2, 4). This says: at this point, increasing w2 moves f upward twice as fast as increasing w1 does — so if you wanted to decrease f as fast as possible, you'd step in the opposite direction, (−2, −4), moving w2 twice as far as w1. This is exactly what gradient descent (Chapter 9) does, at the scale of millions of weights instead of two.

The chain rule

Neural networks are functions built by composing many simpler functions in sequence (layer after layer). The chain rule says the derivative of a composition is the product of the pieces' derivatives:

if y = f(g(x)), then dy/dx = f′(g(x)) · g′(x)
Worked Example — chain rule

Let y = (3x+1)2. Write it as g(x)=3x+1 (so g′(x)=3) composed with f(u)=u2 (so f′(u)=2u). At x=1: g(1)=4, so dy/dx = f′(4)·3 = 8×3 = 24. Check directly: y(1)=16, y(1.01)=(4.03)2=16.24, a change of 0.24 for a 0.01 step — 24×, matching.

Key Insight

Backpropagation (Chapter 9) is nothing more than applying the chain rule automatically, layer by layer, from the network's output error backward to every single weight. There is no separate "backprop math" beyond this rule applied a few dozen times in a row, once per layer.

Chapter 4 · Part I

Probability in Brief: Random Variables, Bernoulli, Expectation

Intuition

A random variable is just a quantity whose value isn't fixed — it's drawn according to some rule each time you "run" it. A coin flip is the simplest possible random variable: it comes out heads or tails, with some probability attached to each. This project uses exactly this idea, deliberately, inside its core mechanism: each of the network's internal "cells" flips a biased coin at every update step to decide whether it's allowed to update at all (Chapter 23).

The Bernoulli distribution

A Bernoulli random variable takes only two values, 1 ("success") or 0 ("failure"), with P(1) = p and P(0) = 1−p, for some fixed probability p between 0 and 1. Written m ∼ Bernoulli(p).

The expectation (average value, over infinitely many repeats) of a random variable is written E[·]. For a Bernoulli variable, E[m] = 1×p + 0×(1−p) = p.

Worked Example — Bernoulli(0.5)

This is a fair-coin flip: p=0.5. Flip it 10 times, and you'd expect about 5 ones and 5 zeros — not exactly 5 every time (that's the "random" part), but 5 is the long-run average: E[m] = 0.5. Now suppose m is used as a gate on some value δ: the update rule is "add δ to the state only if m=1." Over many repeats, roughly half the updates get applied and half get skipped, at whichever locations independently drew a 1.

Key Insight

In this project, every one of the 196 patch positions independently draws its own Bernoulli(0.5) coin flip at every one of the mechanism's internal iterations, deciding whether that specific location's proposed update gets applied this step. Some cells update, some sit still, and which ones do is different every time, even for the same image. Chapter 20 explains why NCA research adopted this on purpose — it is not noise added by accident, it is a stability technique borrowed directly from prior Cellular Automata work.

Chapter 5 · Part I

Big-O Notation: Talking About "How Much Work"

Intuition

If you double the size of an image, how much more computation does processing it take? Twice as much? Four times? A hundred times? Big-O notation is a shorthand for answering exactly this question — not with an exact number (which depends on hardware, implementation, etc.) but with the shape of the growth curve as the input gets large. It ignores constant multipliers and focuses on which variable the cost scales with, and how.

O(n) means "cost grows proportionally to n" — doubling n roughly doubles the cost. O(n2) means "cost grows proportionally to n squared" — doubling n roughly quadruples the cost. The difference between these two shapes is the single most important fact in Part IV of this book.

Worked Example — O(n) vs. O(n2) at this project's actual token count

This project's images are cut into n = 196 patch tokens (Chapter 1). Compare the two growth shapes at this exact value:

QuantityFormulaValue at n=196
Linear costO(n)196
Quadratic costO(n2)38,416

The quadratic quantity is 196× larger than the linear one, at this exact, real token count — not a hypothetical large n, the actual number of patches in every single image this project processes. Standard self-attention (Chapter 15) costs O(n2D): every one of the 196 tokens compares itself against all 196 others. Emergent Attention (Chapter 23) costs O(Kn D2): every token only ever looks at its 8 immediate neighbors, repeated K times — linear in n, not quadratic. Chapter 25 returns to this exact comparison with the project's real D and K values filled in.

Key Insight

"Linear in n instead of quadratic in n" is not a minor implementation detail — it is the entire computational argument for why iterated local computation (Cellular Automata) is even worth considering as a substitute for global attention. Whether that theoretical advantage shows up as an actual speed advantage in this project's measured throughput is a separate, honestly-reported question, addressed in Chapter 25.

Chapter 6 · Part II

The Single Neuron

Intuition

An artificial "neuron" does one small thing: it takes several numbers in, multiplies each by its own importance weight, adds them up, adds one more adjustable number (a bias), and passes the result through a simple nonlinear function. That's the entire unit. A neural network is thousands to billions of these, wired together in layers.

output = activation( w1x1 + w2x2 + … + wDxD + b ) = activation( w · x + b )

Notice the middle term is exactly the dot product plus bias from Chapter 2 — a single neuron is a 1-row linear layer, followed by an activation function (Chapter 7).

Worked Example — one neuron, three inputs

Inputs x = (1, 2, −1), weights w = (0.5, −1, 2), bias b = 0.3.

w·x = 0.5×1 + (−1)×2 + 2×(−1) = 0.5 − 2 − 2 = −3.5. Adding the bias: −3.5 + 0.3 = −3.2. If the activation is ReLU (Chapter 7), the final output is max(0, −3.2) = 0 — this particular neuron did not "fire" for this particular input.

A layer is many neurons applied to the same input in parallel, each with its own weight vector — stack those weight vectors as rows and you get exactly the matrix W from Chapter 2, so a full layer is y = activation(Wx + b). A multi-layer perceptron (MLP) is several such layers chained one after another, each one's output feeding the next one's input. Every "MLP" mentioned anywhere in this project — the update rule inside Emergent Attention (Chapter 23), the feed-forward block inside every Transformer block (Chapter 16) — is exactly this: a small stack of linear layers with activations between them.

Chapter 7 · Part II

Activation Functions: ReLU and Softmax

Intuition

Why not just stack linear layers directly, with no activation function between them? Because a linear function of a linear function is still just a linear function — no amount of stacking gains any expressive power. Activation functions are what let a network represent curved, complex relationships instead of only straight-line ones.

Worked Example — why linear layers alone don't help

Let layer 1 compute y = 2x + 1, and layer 2 compute z = 3y − 4, with no activation function between them. Substituting: z = 3(2x+1) − 4 = 6x − 1. That is still just one linear function of x — a straight line with slope 6. Two layers collapsed into exactly what one layer could already do. This is why every real network inserts a nonlinear activation between linear layers: without it, "depth" is an illusion.

ReLU (Rectified Linear Unit)

The activation used inside the Emergent Attention update MLP (Chapter 23) and throughout this project's networks is the simplest nonlinearity in common use:

ReLU(x) = max(0, x)

It passes positive numbers through unchanged and clamps every negative number to exactly zero. Despite — or because of — this simplicity, it's the default choice for most modern networks: it's cheap to compute, and its derivative is trivial (1 for x>0, 0 for x<0), which keeps gradients (Chapter 3) well-behaved during training.

Softmax

ReLU acts on one number at a time. Softmax acts on a whole vector at once, and is used specifically to turn an arbitrary list of numbers ("logits") into a valid probability distribution — all values between 0 and 1, summing to exactly 1.

softmax(z)i = ezi / Σj ezj
Worked Example — softmax over 3 classes

Suppose a network outputs three raw scores ("logits") for three classes: z = (2.0, 1.0, 0.1) — higher means "more confident in this class," but these numbers aren't probabilities yet (they don't sum to 1 and can be negative).

0.659 + 0.242 + 0.099 = 1.000. The network is now saying "65.9% confident it's class A" — a genuine probability distribution, obtained from arbitrary real-valued scores just by exponentiating and normalizing. Softmax reappears twice more in this book: turning attention scores into weights (Chapter 15), and turning a classifier's final logits into the class probabilities used to compute loss (Chapter 8).

Chapter 8 · Part II

Measuring Wrongness: Loss and Cross-Entropy

Intuition

Before a network can improve, it needs a single number that says how wrong its current prediction is — low when the prediction is good, high when it's bad. That number is called the loss. Training a network is nothing more than adjusting its weights (Chapter 6) to make this one number smaller, using the gradient (Chapter 3) to know which direction "smaller" is in.

Cross-entropy loss

For classification (choosing among several categories, exactly this project's task), the standard loss is cross-entropy: given the model's predicted probability for the correct class, pcorrect, the loss is

L = −log(pcorrect)

This is small when pcorrect is close to 1 (confident and right) and grows rapidly as pcorrect approaches 0 (confident and wrong) — exactly the shape you'd want a penalty to have.

Worked Example — cross-entropy on the softmax output above

Continuing the 3-class example: suppose the true label is class A, with softmax probability pA = 0.659. L = −log(0.659) = 0.417 (natural log). Now compare a worse prediction where the model was less confident in the correct answer, say pA = 0.1: L = −log(0.1) = 2.303 — more than 5× the loss, for a prediction that's "somewhat unsure" rather than "confidently right." This is exactly the signal gradient descent (Chapter 9) uses to push weights toward increasing pcorrect.

Label smoothing

Cross-entropy as defined above pushes the network toward pcorrect = 1.0 exactly — total, unshakeable confidence. In practice this tends to make networks overconfident and can hurt generalization. Label smoothing softens the target: instead of the correct class having target probability 1.0 and every other class 0.0, the correct class gets target 1−ε and the remaining probability ε is spread evenly across the other classes.

Worked Example — label smoothing, ε=0.1, 3 classes

Without smoothing, the target for class A is (1, 0, 0). With ε=0.1 spread over the 2 other classes (each gets ε/2 = 0.05): the target becomes (0.9, 0.05, 0.05). This project uses ε=0.1 across 100 classes (CIFAR-100, Chapter 29), so each incorrect class receives a tiny target of 0.1/99 ≈ 0.001 — negligible per class, but collectively it prevents the loss from ever reaching exactly zero for a "perfect," maximally overconfident prediction, which is precisely the point.

Chapter 9 · Part II

Gradient Descent and Backpropagation

Intuition

Imagine standing on a hillside in fog, trying to reach the lowest point, able to feel only the slope directly under your feet. The obvious strategy: take a step in the downhill direction, feel the new slope, step again, repeat. Gradient descent is exactly this strategy applied to a network's loss (Chapter 8), where "the hillside" is the loss as a function of every weight, and "feeling the slope" is computing the gradient (Chapter 3).

w ← w − η · ∇wLη (eta) is the learning rate — how big a step to take

This is, quite literally, the entire algorithm that trained every model in this project; the only difference is that instead of one weight w, there are millions, and instead of a simple bowl-shaped f, the loss landscape is an extremely complex high-dimensional surface. The mechanics are identical.

Backpropagation

Gradient descent needs the gradient of the loss with respect to every weight in the network, including weights buried in the very first layer, many layers away from where the loss is computed. Backpropagation is the algorithm that computes all of these efficiently, in one backward pass, using nothing more than the chain rule (Chapter 3) applied layer by layer, from the output back to the input.

Intuition

Picture the network as a chain of functions: input → layer 1 → layer 2 → … → loss. To know how a weight in layer 1 affects the loss, the chain rule says: multiply "how layer 1's output affects layer 2's output" by "how layer 2's output affects layer 3's output" … all the way to "how the last layer's output affects the loss." Backpropagation computes this efficiently by starting at the loss and working backward one layer at a time, reusing each layer's result for every earlier layer — instead of recomputing the whole chain from scratch for every single weight.

Key Insight

You will never need to derive a backpropagation formula by hand for this project — the software framework (PyTorch) does it automatically for any computation you define, including the Emergent Attention mechanism in Chapter 23. What matters for understanding the project is knowing what that automatic machinery is doing: repeated chain-rule multiplication, nothing more mysterious than Chapter 3's worked example, just applied many more times.

From plain gradient descent to AdamW

Plain gradient descent (as worked out above) uses the same step size for every weight and has no memory of past steps. In practice this is slow and easily gets stuck oscillating in narrow valleys of the loss surface. Adam improves on it by keeping a running average of each weight's recent gradients (so it builds "momentum" in a consistent direction) and a running average of each weight's recent squared gradients (so weights with noisy, erratic gradients get automatically smaller, more cautious steps, and weights with smooth, consistent gradients get to move faster). AdamW (used throughout this project) additionally separates "weight decay" — a small constant pull of every weight toward zero, which discourages any single weight from growing unnecessarily large and helps prevent overfitting (Chapter 10) — from the adaptive gradient step, applying it directly rather than folding it into the gradient calculation the way older implementations did. This project uses AdamW with weight decay 0.05 for every model reported (Appendix A of the paper).

Chapter 10 · Part II

The Full Training Recipe

Intuition

Gradient descent (Chapter 9) tells you how one weight update works. But real training runs it hundreds of thousands of times, over a schedule of settings that change as training progresses, plus a set of tricks that make the network generalize to images it has never seen rather than merely memorize the ones it was shown. This chapter builds every piece of the exact recipe used for every model in this project, one at a time.

Batches and epochs

Computing the exact gradient over the entire 50,000-image training set before every single weight update would be extremely slow. Instead, training uses mini-batches: a small random subset of images (this project uses batch size 64) at a time, computing an approximate gradient from just those 64 images, and updating weights immediately. One full pass through the entire training set, in batches, is one epoch. This project trains for 300 epochs — 300 full passes over the data, each broken into many 64-image batches.

Learning rate schedule: cosine annealing with warmup

The learning rate η (Chapter 9) doesn't stay fixed throughout training. Two adjustments are used together:

Intuition

Warmup: for the first few epochs, start the learning rate near zero and ramp it up gradually. Early in training the weights are random and the gradients can be erratic; a large step size applied immediately can knock the network into a bad region it never recovers from. Ramping up gives the network a few epochs to settle before taking full-sized steps. Cosine annealing: after warmup, decrease the learning rate smoothly, following the shape of one quarter of a cosine curve, down toward (near) zero by the end of training. Large steps early (once warmed up) let the network explore broadly; small steps late let it settle precisely into a good minimum without overshooting.

Overfitting, and why augmentation fights it

Definition

Overfitting: when a network becomes so specialized to the exact training images it has seen that it stops generalizing to new ones — training accuracy keeps climbing while accuracy on held-out test images stalls or drops. With only 50,000 training images and millions of weights, overfitting is a real risk, especially since this project trains every model from random initialization with no ImageNet pretraining (Chapter 29). The recipe below exists almost entirely to fight this.

Mixup and CutMix

Mixup creates new training examples by blending two real images and their labels together: pick a mixing ratio λ (drawn randomly, biased toward values near 0 or 1 by a Beta distribution), then xnew = λx1 + (1−λ)x2, and correspondingly blend the two labels: ynew = λy1 + (1−λ)y2. CutMix does the analogous thing spatially — cutting a rectangular patch from one image into another, with the label mixed in proportion to the patch's area.

Worked Example — Mixup on two toy 3-class labels

Image 1 is class A (target (1,0,0)), image 2 is class B (target (0,1,0)), and the draw gives λ=0.7. The blended image is 70% image 1's pixels plus 30% image 2's pixels; the blended target is 0.7×(1,0,0) + 0.3×(0,1,0) = (0.7, 0.3, 0). The network is trained to predict this exact soft target — "mostly class A, somewhat class B" — on an image that is genuinely a blend of the two, which forces it to learn more robust, less brittle decision boundaries than always seeing pure, single-class images.

This project applies Mixup (α=0.8) and CutMix (α=1.0) each with 50% probability per batch, on every CIFAR-100 model. Chapter 37 covers a specific, important exception: Mixup/CutMix were disabled for the BUSI ultrasound experiments, and explains exactly why with a worked example of what goes wrong when they aren't.

RandAugment and Random Erasing

RandAugment randomly applies a sequence of simple image transformations (rotation, color shifts, sharpness changes, and more) at random strengths, forcing the network to be invariant to superficial variation rather than the details of any single training image. Random Erasing randomly blacks out a rectangular region of the image (this project: with 25% probability per image), forcing the network to classify correctly even when part of the object is occluded — directly relevant to this project's later corruption-robustness experiments (Chapter 33), since it means every model, not just the NCA-based ones, was already trained with some exposure to partial information loss.

Exponential Moving Average (EMA) of weights

Because mini-batch gradients (Chapter 9) are noisy approximations, the weights bounce around somewhat even late in training, instead of settling perfectly smoothly. EMA maintains a second, separate copy of the weights that is updated as a slow-moving average of the real (noisy) training weights, and it is this smoothed copy that is actually evaluated and reported.

θEMA ← d · θEMA + (1−d) · θcurrentd = decay rate, this project uses d = 0.9999
Worked Example — EMA smoothing a noisy sequence

Using a much smaller decay (d=0.5, for a short example you can trace by hand) on a toy weight bouncing between 1 and 3 every step: θ=1, 3, 1, 3, 1… Starting θEMA=1: step to 3 → 0.5×1+0.5×3=2.0; step to 1 → 0.5×2.0+0.5×1=1.5; step to 3 → 0.5×1.5+0.5×3=2.25; step to 1 → 0.5×2.25+0.5×1=1.625. The EMA settles toward the middle of the oscillation (2.0) instead of bouncing with it. At the project's real decay of 0.9999, each update moves the EMA copy only 0.01% of the way toward the current weights — an extremely slow, heavily smoothed average that damps out batch-to-batch noise almost entirely.

AMP (Automatic Mixed Precision) and gradient clipping

Every number in a network is normally stored with 32 bits of precision (float32). AMP performs most computation in 16-bit precision instead, which is roughly twice as fast and uses half the memory on modern GPUs, while keeping a small number of numerically sensitive operations (like the final loss accumulation) in 32-bit precision to avoid instability. Gradient clipping (this project: clipped to a maximum norm of 1.0) simply rescales the gradient if its overall magnitude exceeds a threshold, preventing a single unusually large, noisy gradient from taking a destructively large step.

Reproducibility: the random seed

Every "random" choice in this recipe — which images land in which batch, Mixup's λ, RandAugment's random transforms, the Bernoulli gate inside Emergent Attention (Chapter 23) — is generated by a pseudo-random number generator that is fully determined by a starting number called the seed. Fixing the seed (this project defaults to seed 42, with seeds 123 and 7 also used for specific multi-seed checks in Chapters 31 and 37) means the entire sequence of "random" events is exactly reproducible — rerunning the same command with the same seed reproduces the identical training run, which is what makes the project's Reproducibility Statement (a real, checkable claim in the paper) possible at all.

Convolution: Sliding a Small Window Over an Image

Intuition

Take a small grid of numbers (a "kernel" or "filter," commonly 3×3), lay it over one corner of an image, multiply each overlapping pair of numbers, sum the results into a single output number, then slide the kernel one pixel over and repeat, until it's swept across the entire image. The output is a new, usually smaller, grid — one number per position the kernel stopped at. That sliding-multiply-sum procedure is a convolution (more precisely, what deep-learning frameworks implement is technically cross-correlation — true mathematical convolution flips the kernel first; the distinction almost never matters in practice, and this book uses "convolution" the way the field does, to mean the unflipped sliding operation).

Depthwise convolution

A color image (or, in this project, a 192-channel patch grid, Chapter 1) has many channels, not one. A standard convolution mixes all input channels together into each output channel. A depthwise convolution instead applies a separate, independent kernel to each channel on its own, never mixing channels together spatially. This project's perception step (Chapter 23) is depthwise specifically so that each of the 192 channels is filtered independently and identically, with no cross-channel mixing happening inside the convolution itself — any mixing across channels happens afterward, inside the update MLP (Chapter 6).

Intuition

A single 3×3 convolution, applied once, lets each output value "see" only its own immediate 3×3 neighborhood in the input — it has no idea what's happening two pixels further away. But stack the operation, applying it again to its own output, and something changes: each position in the second application already summarizes its own 3×3 neighborhood of first-application outputs, each of which already summarized its own neighborhood — so after two applications, one output value has been influenced by a 5×5 region of the original input. The receptive field of a position is exactly this: the region of the original input that can possibly affect its value, and it grows with every additional layer or iteration of local computation.

Turning an Image into Tokens

Intuition

A Transformer (Chapter 16) was originally designed for language — sequences of word tokens. A Vision Transformer (ViT) makes an image look like such a sequence: cut it into a grid of small square patches, and treat each patch as one "token," exactly the way a sentence is a sequence of word tokens.

Patch embedding

Recall from Chapter 1: this project uses 224×224 images cut into 16×16-pixel patches, giving a 14×14 grid, n=196 patches. Each raw patch is 16×16×3 = 768 numbers. A single linear layer (Chapter 2) — the patch embedding — maps each flattened 768-number patch down to a D=192-dimensional vector. This is exactly the "linear layer" worked example from Chapter 2, just with a 768-in, 192-out weight matrix instead of the tiny 2-in, 3-out one used there.

The CLS token

Alongside the 196 patch vectors, standard ViT prepends one extra, learned vector called the CLS token (short for "classification"). It carries no image information of its own at the start; its entire purpose is to gather information from every patch token via attention (Chapter 15) as it passes through the network, so that by the final layer, the CLS token's vector summarizes the whole image and can be handed to a small classifier head to produce the final prediction.

Note — this project doesn't always use CLS this way

This project's Hybrid and Pure NCA-ViT models still carry a CLS token through the network (so it's directly comparable to standard ViT/DeiT), but they classify using global average pooling (GAP) over the 196 patch tokens instead of reading the CLS token. The reason is Chapter 23's design: the CLS token is deliberately excluded from the NCA computation in every NCA block, so for the first six layers of the Hybrid model, CLS never receives any image-dependent information at all — reading it directly for classification would mean reading a vector that's blind to everything the network's early layers actually computed. GAP pooling over the patch tokens sidesteps this entirely. Chapter 24 explains the CLS-isolation design choice itself in full.

Position embeddings

A convolution (Chapter 11) inherently knows about spatial order — a 3×3 kernel only ever looks at adjacent pixels. Self-attention (Chapter 15) has no such built-in sense of position: mathematically, it treats the sequence of tokens as an unordered set unless something explicitly tells it otherwise. A learned position embedding — one more vector, one per patch position, added directly to that patch's content vector — is how ViT gives the network access to "where in the grid did this token come from."

Self-Attention: Query, Key, Value

Intuition

For each token, self-attention asks three separate questions, computed from that token's vector by three separate learned linear layers (Chapter 2): a Query ("what information am I looking for?"), a Key ("what information do I advertise having?"), and a Value ("what information will I actually hand over, if asked?"). Every token's Query is compared — via dot product (Chapter 1) — against every other token's Key, producing a relevance score for every pair. Those scores are turned into weights (via softmax, Chapter 7), and each token's final output is a weighted blend of every token's Value, weighted by how relevant that token's Key was to this token's Query.

Key Insight

Self-attention's defining property, visible directly in the worked example: every token's output can depend on every other token, in a single step, with the dependency strength (the weights) determined dynamically by content, not fixed in advance the way a convolution's neighborhood is. This is exactly what Emergent Attention (Chapter 23) gives up, in exchange for locality and iteration — and exactly the trade this whole book is building toward being able to evaluate precisely.

Chapter 16 · Part IV

Multi-Head Attention and the Transformer Block

Intuition

One attention computation captures one notion of "relevance." Real Transformers run several attention computations in parallel — "heads" — each with its own separate Query/Key/Value projections, on separate, smaller slices of the token's dimension, so different heads are free to specialize in different kinds of relationships (one might learn to track color similarity, another spatial adjacency, and so on), before their outputs are concatenated back together and passed through one more linear layer.

With D=192 and 3 heads (the configuration used for every attention-based model in this project, including the second half of the Hybrid architecture), each head operates on a D/3 = 64-dimensional slice, running the exact procedure from Chapter 15 independently, then the three 64-dimensional outputs are concatenated back into a 192-dimensional vector and passed through a final linear projection.

LayerNorm

Before both the attention step and the MLP step, each token's vector is passed through Layer Normalization: subtract that token's own mean and divide by that token's own standard deviation, then rescale with two learned parameters. This keeps the numbers flowing through the network in a stable, consistent range at every layer, which makes gradient-based training (Chapter 9) far more reliable in deep networks.

Worked Example — LayerNorm on one 4-number vector

x = (2, 4, 4, 6). Mean = 4. Variance = average of (2−4)2, (4−4)2, (4−4)2, (6−4)2 = (4+0+0+4)/4 = 2. Standard deviation = √2 ≈ 1.414. Normalized: ((2−4)/1.414, (4−4)/1.414, (4−4)/1.414, (6−4)/1.414) = (−1.414, 0, 0, 1.414). Every LayerNorm output has mean 0 and standard deviation 1 by construction — before the network's own learned rescaling is applied on top.

The full Transformer block

z′ = z + MHSA(LN(z)),   z = z′ + MLP(LN(z′))

Two sub-layers, each wrapped in a residual connection (the "z + …" pattern): the sub-layer's output is added to the input, rather than replacing it. This matters directly for training deep networks: if a sub-layer's contribution during early training is close to zero, the residual connection guarantees the block still passes its input through essentially unchanged, rather than corrupting it — gradients (Chapter 3) can flow straight through the "+" unimpeded even when the sub-layer's own gradient is small or noisy. Chapter 24 shows Emergent Attention leans on this same idea deliberately, via zero-initialization, to guarantee it starts training as an exact identity function.

The Cost of Attention, and Why It Matters

Intuition

Chapter 15's worked example computed one token's output by comparing it against all 3 tokens. For n tokens, every one of the n tokens must be compared against all n tokens (itself included) — n×n comparisons in total. This is exactly the O(n2) growth from Chapter 5, and it is standard self-attention's defining cost.

Cost of one MHSA layer ≈ O(n2D)

At this project's n=196, D=192: roughly 1962×192 ≈ 7.37 million multiply-accumulate operations, per attention layer, per image, just for the attention step itself (before the MLP sub-layer). This cost is why Swin-Tiny (Chapter 18) restricts attention to local windows rather than the full image, and it is the exact cost Emergent Attention (Chapter 23) avoids by replacing global comparison with local, iterated computation — Chapter 25 returns to this comparison with both mechanisms' real operation counts filled in.

The Baselines: ViT, DeiT, Swin

Intuition

This project doesn't just report Emergent Attention's numbers in isolation — it compares against three well-established Vision Transformer designs, trained under the exact same recipe (Chapter 10) for a fair comparison. Knowing what distinguishes each one is necessary to read the results tables in Part VIII.

ViT (Vision Transformer)

The original design (Dosovitskiy et al., 2021): patch embedding, CLS token, position embeddings, a stack of standard Transformer blocks (Chapter 16), and a classifier reading the final CLS token. ViT proved that a pure-attention architecture, with no convolutions anywhere, could match convolutional networks — but the original version needed enormous pretraining datasets to get there.

DeiT (Data-efficient image Transformer)

DeiT's original contribution was a training recipe (knowledge distillation from a convolutional teacher network, plus heavy augmentation) that let a ViT-shaped architecture train well on much smaller datasets without that massive pretraining. In this project, "DeiT-Tiny" refers to the architecture configuration DeiT introduced (D=192, depth 12, 3 heads — the same D=192 this project's own models use, chosen specifically to keep model width comparable) trained from scratch under this project's own recipe (Chapter 10), not DeiT's original distillation procedure — there is no separate teacher network anywhere in this project. It functions here as the closest architectural sibling to this project's own token count and embedding width, differing only in the token-mixing mechanism (standard MHSA throughout, vs. Emergent Attention for some or all layers).

Swin Transformer

Swin reintroduces locality into attention: instead of every token attending to all 196 others, tokens are grouped into small local windows, and attention is computed only within each window. Layers alternate between two window arrangements ("shifted windows") so that information can still eventually flow across window boundaries over depth, and the grid is periodically downsampled (merging groups of nearby tokens into fewer, wider tokens) as the network gets deeper, mimicking the pyramid structure of classical convolutional networks. Swin-Tiny is substantially larger than the other baselines here (27.60M parameters vs. 5.54M for ViT/DeiT-Tiny), and it is the strongest baseline on clean accuracy in this project's results (Chapter 30).

Key Insight

Swin already demonstrates that some form of locality helps Vision Transformers — it just achieves locality through windowing and hierarchy, at a large parameter cost. This project's core question, answered starting in Part VI, is whether a much smaller, non-learned form of locality — a fixed edge-detection kernel, iterated instead of windowed — can capture a related benefit at a fraction of the parameter count, and whether that benefit has a precise, checkable shape rather than being a vague "helps a bit, generally."

Conway's Game of Life: Complexity from a Local Rule

Intuition

A cellular automaton is a grid of cells, each in one of a small number of states, updated all at once, over and over, by a rule that only ever looks at each cell's immediate neighbors. Conway's Game of Life (1970) is the most famous example: every cell is either "alive" or "dead," and the entire rule is three sentences long — yet it produces gliders, oscillators, and structures complex enough to be, in a formal sense, a general-purpose computer. Nothing in the rule itself is complicated; the complexity comes entirely from applying it everywhere, simultaneously, over many steps.

Definition — the Game of Life rule

For every cell, count its living neighbors among the 8 surrounding cells, then: a living cell with 2 or 3 living neighbors stays alive (otherwise it dies); a dead cell with exactly 3 living neighbors becomes alive (otherwise it stays dead). Every cell on the grid applies this same rule at the same time, using only the previous step's neighbor counts.

Key Insight

No cell in the Game of Life ever sees more than its 8 immediate neighbors, and no cell ever "knows" the global pattern it's part of. Complex, structured, long-range behavior emerges anyway, purely from repetition. This single observation is the seed the project's name comes from: Emergent Attention — attention-like, long-range information flow, emerging from a rule that never itself looks further than its own neighborhood.

Chapter 20 · Part V

Neural Cellular Automata: Learning the Local Rule

Intuition

The Game of Life's rule was hand-written by a mathematician. A Neural Cellular Automaton (NCA) replaces the hand-written rule with a small neural network (Chapter 6), trained so that repeating it produces some desired outcome. The landmark example, Growing Neural Cellular Automata (Mordvintsev et al., 2020), trains a local rule so that starting from a single "seed" cell and iterating produces an entire target image — the image literally grows, cell by cell, from nothing, using a rule no more complex per-step than the Game of Life's, just learned instead of designed.

Perception, then update

Every NCA step follows the same two-part structure, and it should look immediately familiar — it's built directly from Parts III and II of this book:

  1. Perceive: each cell looks at its 3×3 neighborhood using a small set of fixed convolution filters (Chapter 11) — the original Growing NCA work used exactly the Sobel-X and Sobel-Y filters from Chapter 12, plus the cell's own raw value (the Identity filter), the same three filters this project reuses unchanged.
  2. Update: the perceived values are fed into a small neural network (an MLP, Chapter 6) that outputs a small change, added to the cell's current state. Every cell on the grid runs the same network, with the same weights — a rule shared identically across every position, exactly like the Game of Life's one rule applying to every cell.

Stochastic updates

Growing NCA introduced one more deliberate ingredient: at each step, only a random subset of cells actually apply their computed update (a Bernoulli(p) gate per cell, Chapter 4) — the rest sit still for that step, even though they computed an update. This is not an accident or a regularization afterthought; the original paper found that without it, cells naturally fall into perfect lockstep synchronization, which turns out to be a fragile, unrealistic assumption (real biological growth, which the technique is loosely inspired by, is never perfectly synchronized across cells) and produces less stable, less self-repairing growth patterns.

Key Insight — self-repair

A striking property of trained Growing NCA models: if part of the grown image is deleted mid-training-run or after training, the surviving cells' local rule — run purely from local neighbor information, with no global "look at the whole picture" step anywhere — regrows the missing region. No cell was ever explicitly trained to "notice damage"; the same local update rule that grows the image from a seed also happens to repair it, because damaged regions look locally similar to early-growth regions the rule already knows how to handle. This project's later robustness results (Part VIII) are, in spirit, the same phenomenon applied to noise instead of physical deletion: a mechanism built from local, iterated correction turns out to resist a class of input corruption it was never explicitly trained against.

Chapter 21 · Part V

Why Iteration Can Substitute for Global Attention

Intuition

Three ideas from the last three parts of this book now combine into the project's actual research question. Self-attention (Chapter 15) gives every token global reach in one step, at O(n2) cost (Chapter 17). A single convolution (Chapter 11) gives every position only local reach, but stacking or iterating it grows that reach linearly (Chapter 13), at O(n) cost per step. A Neural Cellular Automaton (Chapter 20) is exactly this iterated local computation, with a learned update rule, and demonstrated properties — like self-repair — that come specifically from being local and iterated rather than global and single-shot.

Put together, these three facts suggest a genuine, testable question, rather than just an analogy: if you replace a Transformer's global attention layer with enough iterations of a local NCA-style rule, does the network still work — and if it does, does it inherit any of the NCA-family's characteristic robustness properties, in a form precise enough to predict, not just observe after the fact?

Key Insight — how this differs from simply "combining" NCA and attention

Prior work had already combined these two ideas, but always by keeping attention as the primary mechanism and adding NCA around it — NCA blocks inserted between attention layers (AdaNCA, 2024), or attention fused into the NCA update rule itself (ViTCA, 2022). Neither removes attention. This project's method, covered starting next chapter, asks the more direct version of the question: not "does adding some NCA help attention," but "can iterated local NCA dynamics fully replace global attention as the token mixer" — and if the resulting model is measurably different in its robustness behavior, can that difference be predicted in advance, rather than just measured after training and reported as a number.

Chapter 22 · Part VI

The Idea, in One Paragraph

Intuition — no formulas at all

Take a standard Vision Transformer block (Chapter 16) and delete its self-attention step. In its place, put a Neural Cellular Automaton (Chapter 20): every patch looks at its 8 immediate neighbors using two fixed edge-detecting filters plus a raw-value filter (Chapter 12), feeds what it sees into one small shared neural network (Chapter 6), and nudges its own value slightly based on the result — but only if a coin flip (Chapter 4) for that specific cell, this specific step, comes up in its favor. Do this four times in a row, each time using the updated grid from the step before, so information can spread outward one neighborhood at a time (Chapter 13). After four rounds, add up everything that changed and hand it to the rest of the network, exactly the way a standard attention block's output gets added back (Chapter 16). Do this for the first half of the network's layers; use ordinary global attention (Chapter 15) for the second half. That whole paragraph is Hybrid NCA-ViT — the project's main architecture.

The rest of this part makes every sentence above precise: exact shapes, exact formulas, one full worked numeric pass through the mechanism, and a justification for each of the four non-obvious choices (fixed filters, zero-init, coin-flip gating, and never letting the CLS token join in).

The Full Mechanism, Worked Numerically

perccenter = (0, 0, 5). h = ReLU(W1·perc + b1),    δ = W2·h + b2

Later in training, once W2, b2 have moved away from zero — say W2 = (0.3, 0.1), b2=0 (again illustrative): δ = 0.3×5 + 0.1×0 + 0 = 1.5. The center cell now has a nonzero proposed update.

Step 3 — the stochastic gate

st+1 = st + mt ⊙ δt,  mt ∼ Bernoulli(p)  (training)
st+1 = st + δt  (inference)
Worked Example — the coin flip, p=0.5

During training, before the update above is applied, each cell independently draws m ∼ Bernoulli(0.5) (Chapter 4). If m=1 (heads): the center cell's new value is 5 + 1×1.5 = 6.5. If m=0 (tails): the update is skipped entirely for this cell, this step: the center cell stays at 5, even though δ was computed and was nonzero. At evaluation/inference time, the coin flip is removed entirely and every cell always updates — the stochasticity is a training-time stabilization technique (Chapter 20), not part of the deployed model's behavior.

Step 4 — iterate, then output

Steps 1–3 repeat K=4 times total, each time operating on the updated grid from the previous iteration — so on iteration 2, the center cell's neighbors (which received no direct update on iteration 1, since their own local neighborhoods differed) begin to feel the center cell's change through their own perception step, and the disturbance spreads outward exactly as Chapter 13's receptive-field argument predicts: one ring of neighbors per iteration, reaching a 9×9-patch region after all K=4 iterations. After the last iteration, the total accumulated change is handed back to the residual stream, with a zero delta reinserted for the CLS token that was set aside in Step 0:

Δ = sK − s0       z ← z + DropPath( [0CLS ; Δ] )

Chapter 24 · Part VI

Four Design Decisions, and Why Each Was Made

1. Why are the perception filters fixed, not learned?

A standard convolution layer learns its filters from data. This project deliberately freezes them at the classic Sobel-X/Sobel-Y/Identity values (Chapter 12) instead, for three reasons: (a) it guarantees the network has a known, interpretable, edge-and-value-detecting inductive bias from the very first training step, regardless of how training goes; (b) every model in this project trains entirely from random initialization, with no large-scale pretraining (Chapter 10) — removing these parameters from the pool of things that must be learned from a relatively small dataset (50,000 CIFAR-100 images, or as few as 625 for BUSI, Chapter 37) is a direct sample-efficiency argument; (c) the codebase does include an optional flag to unfreeze them, but no headline result in the paper uses it — that experiment is future work, reported honestly as not yet run rather than implied to have been tried and confirmed unnecessary.

2. Why is the update MLP's output layer zero-initialized?

Recall from Chapter 23: with W2, b2 = 0, the block computes δ≡0 for every cell, meaning the entire Emergent Attention block is an exact identity function at the start of training — it changes nothing, no matter the input. This connects directly to Chapter 16's residual-connection discussion: a freshly-initialized, non-zero sub-layer inserted into a deep residual network can inject large, essentially random perturbations into a signal that the rest of the (also freshly-initialized) network hasn't learned to handle yet, which can destabilize early training or require a careful warm-up schedule to avoid. Zero-initializing the output projection sidesteps the problem entirely: training begins as if the NCA blocks were transparent, and they only gradually begin contributing as W2 moves away from zero under gradient descent (Chapter 9) — no NCA-specific warm-up schedule is needed anywhere in the training recipe (Chapter 10).

3. Why gate updates with a coin flip instead of always updating?

This is inherited directly from Growing NCA's stabilization practice (Chapter 20): always-synchronous updates encourage the network to rely on every cell updating in perfect lockstep, a fragile assumption. Stochastic gating (Chapter 4) breaks that reliance during training, and empirically NCA-family models trained this way exhibit better stability and the self-repair property discussed in Chapter 20. It also has a side effect familiar from a different, well-known regularization technique: like Dropout (which randomly zeroes out whole neurons during training to prevent over-reliance on any single one), randomly skipping a cell's update forces the surrounding cells' rule to remain informative even when any individual neighbor might sit out a given step — discouraging brittle dependence on any one specific update actually landing.

4. Why is the CLS token never allowed to join the NCA grid?

The entire justification for calling this rule "local and shared" — the same justification that makes the receptive-field argument (Chapter 13) and the Big-O argument (Chapter 17, Chapter 25) valid at all — rests on every cell obeying the identical rule, operating on a well-defined spatial neighborhood. The CLS token (Chapter 14) has no spatial position; it doesn't correspond to any patch of the image. Letting it participate would force an arbitrary choice (what is its "neighborhood"?) and would risk turning it into a special-cased shortcut — an information sink that quietly breaks the "identical rule, everywhere" property the whole mechanism depends on. The block instead returns an explicit zero delta for CLS at every NCA layer (visible directly in Step 4 of Chapter 23's worked example), and Chapter 14 already covered the practical consequence: since CLS never receives image-dependent information while passing through any NCA block, the Hybrid and Pure NCA-ViT models classify using global-average-pooled patch tokens (Chapter 14) instead of reading CLS.

Hybrid NCA-ViT

Intuition

This is the project's main architecture, and the one Chapter 22's one-paragraph summary describes: the first half of a 12-block network uses Emergent Attention, the second half uses standard multi-head self-attention. Everything about it — patch embedding, position embeddings, the CLS token that gets carried along but never read — is built entirely from pieces this book has already covered.

The full pipeline, in order: an image is cut into 196 patches and linearly embedded to D=192 (Chapter 14); a CLS token and position embeddings are added; the sequence passes through LN=6 Emergent Attention blocks (Chapter 23, each with K=4 iterations, hidden width 384); then through LA=6 standard Transformer blocks (Chapter 16, 3 attention heads); finally, the 196 patch tokens (not CLS — Chapter 24, reason 4) are averaged together (global average pooling, Chapter 14) and passed to a small classifier head. Total: 6.46 million parameters.

Key Insight — why this specific ordering, early-NCA then late-attention?

The intuition (defended empirically in Chapter 31's ablation, not just asserted here) is a division of labor: early layers work on low-level, still-local image structure — edges, textures, small patterns — exactly the regime local, iterated computation (Part III, Part V) is naturally suited to. Late layers work on already-abstracted, semantic, class-relevant features, where directly comparing distant parts of the image in one step (global attention, Chapter 15) is more valuable than continuing to refine local neighborhoods. The architecture doesn't assume this division is correct; Chapter 31 tests it directly by trying every other split.

CIFAR-100 and "Top-1 Accuracy"

Intuition

Before any robustness question can be asked, a network first has to be shown to actually work: trained to classify ordinary, uncorrupted images correctly. CIFAR-100 is the dataset used for this — 50,000 training images and 10,000 test images, spread across 100 object categories, small enough to train many models from scratch on a single workstation GPU, which matters because every model in this project (Chapter 10) is trained from random initialization, with no large-scale pretraining to fall back on.

CIFAR-100's native images are only 32×32 pixels; this project bicubically upsamples them to 224×224 to match the patch-embedding pipeline (Chapter 14, 16×16 patches × 14×14 grid). It's important to be precise about what upsampling does and doesn't do: it does not add any real information the camera didn't originally capture — it stretches the existing 32×32 pixels smoothly across a larger canvas. The resulting images are genuinely lower-detail than a native 224×224 photograph would be; this is a known property of the setup, not a hidden flaw, and it applies identically to every one of the five architectures compared, so it doesn't advantage or disadvantage any of them relative to the others.

Top-1 and Top-5 accuracy

For each test image, the network outputs a probability (via softmax, Chapter 7) for all 100 classes. Top-1 accuracy is the fraction of test images where the single highest-probability class is the correct one. Top-5 accuracy is more forgiving: the fraction of images where the correct class appears anywhere among the network's 5 highest-probability guesses.

Worked Example — top-1 vs. top-5, one image

True label: "otter." Network's top 5 guesses, ranked: (1) beaver, (2) otter, (3) seal, (4) mink, (5) platypus. Chapter 32 · Part VIII

Adversarial Robustness: FGSM and PGD

Intuition

An adversarial example is an input deliberately, minimally altered — often imperceptibly to a human — specifically to fool one particular trained network, by using that network's own gradient (Chapter 3) against it. Where ordinary training nudges weights downhill on the loss (Chapter 9), an adversarial attack nudges the input pixels uphill on the loss instead — same gradient machinery, opposite direction, opposite target variable.

FGSM (Fast Gradient Sign Method)

xadv = x + ε · sign( ∇x L(θ, x, y) )

∇xL is the gradient of the loss with respect to the input pixels (not the weights — exactly Chapter 3's gradient machinery, just differentiating through the network to the input instead of stopping at the weights). sign(·) keeps only the direction of each pixel's gradient (+1 or −1), discarding its magnitude. ε is a small fixed budget controlling how far any single pixel is allowed to move.

Worked Example — one FGSM step, two pixels

A toy 2-pixel image, x = (0.50, 0.20), and a (illustrative, invented) gradient of the loss with respect to these two pixels: ∇xL = (−0.30, +0.10). Taking the sign: (−1, +1). With budget ε=0.03: xadv = (0.50 − 0.03, 0.20 + 0.03) = (0.47, 0.23). Each pixel moved by exactly ±ε, in whichever direction the gradient said would increase the loss fastest — the same one-step logic as Chapter 9's gradient-descent worked example, run in reverse, on the input instead of the weights.

PGD (Projected Gradient Descent)

FGSM takes exactly one step. PGD takes many smaller steps (this project: 20, hence "PGD-20"), each one an FGSM-style gradient step, followed by clipping the result back within the allowed ε-budget of the original image if it strayed outside. Because it's allowed to iterate and correct course, PGD finds a far more damaging perturbation within the same budget than a single FGSM step can — it is the standard way to measure a network's worst-case robustness under a given perturbation budget, assuming the attacker has full access to the network's gradients ("white-box" access).

Chapter 33 · Part VIII

Corruption Robustness: CIFAR-100-C

Intuition

Adversarial attacks (Chapter 32) are a worst-case, an intelligent attacker deliberately exploiting one specific network. Corruption robustness asks a different, often more practically relevant question: how does the network handle ordinary, non-adversarial degradation — sensor noise, motion blur, fog, JPEG compression — the kind of thing a real camera or imaging device produces without anyone trying to fool the network at all? CIFAR-100-C (Hendrycks & Dietterich, 2019) is a standard benchmark for exactly this: the CIFAR-100 test set, with 19 different corruption types each applied at 5 severity levels, none of them computed adversarially or tailored to any specific model.

Chapter 34 · Part VIII

Mechanism Verification: Representation Drift

Intuition

Chapter 33's frequency-specific pattern is a fact about accuracy — the network's final answer. It doesn't, by itself, prove anything about why. This chapter tests the proposed explanation — "iterated local averaging suppresses independent, per-pixel additive noise" — directly, by measuring what happens inside the network, without training anything new or looking at whether any prediction was right or wrong.

Cosine similarity and drift

Recall the dot product (Chapter 1) measures how much two vectors "point the same way," but its raw value also depends on the vectors' lengths. Cosine similarity divides that out, comparing pure direction:

cos(a, b) = (a · b) / (|a| |b|)|a| = √(a·a), the vector's length (Chapter 1)

Cosine similarity ranges from +1 (pointing identically) through 0 (perpendicular, unrelated) to −1 (pointing exactly opposite). This project defines drift as 1 minus this value:

drift = 1 − cos( fclean, fcorrupted )
Worked Example — drift between a clean and a corrupted feature vector

Toy 3-dimensional feature vectors (illustrative): fclean = (3, 4, 0), fcorrupted = (3, 3, 1).

Dot product: 3×3 + 4×3 + 0×1 = 9+12+0 = 21. Lengths: |fclean| = √(9+16+0) = √25 = 5; |fcorrupted| = √(9+9+1) = √19 ≈ 4.359.

cos = 21 / (5×4.359) = 21 / 21.795 ≈ 0.9635. drift = 1 − 0.9635 = 0.0365. A small drift, meaning corruption barely rotated this particular feature vector's direction — if this were a real model's classifier-input feature, it would suggest the corruption had little effect on what the classifier actually "sees," largely independent of whether the final prediction changed.

Which feature, exactly?

"Drift" is only a meaningful test of this network's actual robustness if it's measured at the exact vector the classifier reads to make its decision — not some arbitrary internal layer. Recall from Chapter 14: ViT and DeiT classify from the CLS token; Swin and both NCA models classify from GAP-pooled patch tokens. This project hooks each model's own real pre-head input specifically, per architecture.

The falsification test

Intuition — what makes a claim scientific rather than just descriptive

A claim earns real evidential weight not just by matching data after the fact, but by having made a specific, risky prediction in advance — one that could have come out wrong. If the theory here ("local averaging suppresses independent additive noise but spreads sparse extreme-valued outliers instead of rejecting them") is right, it doesn't just predict the Hybrid model should be more stable in general — it predicts one specific exception: impulse noise (isolated, extreme-valued pixels, unlike the smoothly-distributed additive noise the mechanism is suited to) should show the opposite pattern, with the Hybrid model's features drifting more, not less, than DeiT's. This is a prediction that could have simply failed to show up.

It didn't fail. Impulse noise is the only corruption, of all 19, where the Hybrid model's features are less stable than DeiT's — drift 6.8% higher (relative) than DeiT, compared to a 16–26% reduction on the corruptions where the Hybrid model wins. It is also the only corruption family with a large accuracy loss (Chapter 33's table). The sign of the exception was predicted before the drift numbers were computed, not pattern-matched afterward.

Correlation, and an honest caveat about it

A correlation coefficient, r, summarizes how tightly two quantities move together across many data points: r=+1 means they move in perfect lockstep, r=0 means no relationship, r=−1 means they move in perfect opposition. The paper reports r=0.17 between drift-reduction and accuracy-gap across all 19 corruptions — weak — but r=0.77 — strong — restricted to the 11 corruptions where baseline accuracy is under 65%.

Pitfall — reported as descriptive, not as proof

The 65% threshold was chosen after looking at the data, to explain why near-ceiling corruptions (where a baseline is already, say, 90% accurate) have almost no headroom left for extra representational stability to convert into extra accuracy — there's nowhere left for the number to go up. Because the threshold was chosen after the fact rather than fixed in advance, the paper explicitly labels this split as descriptive rather than as a pre-registered statistical test, and states clearly that the sign result (the falsification test above) is the part that carries real evidential weight, while the magnitude/correlation split is offered only as a plausible explanation for why the correlation isn't stronger everywhere, not as independent proof of anything.

Chapter 35 · Part VIII

Case Study — the Bug in the Drift Measurement

Intuition

Chapter 34 presented the drift-mechanism result as if it emerged cleanly on the first attempt. It didn't. This chapter tells what actually happened, because catching your own methodological error before anyone else does — and understanding precisely why it was wrong, not just that the numbers looked off — is itself part of doing this project carefully, and worth being able to explain to a mentor or a reviewer exactly as it happened.

What went wrong, the first time

The first version of this analysis measured drift (Chapter 34) at one fixed, specific mid-network layer, applied uniformly to every one of the five architectures — the same layer index, regardless of which model was being probed. The result: the Hybrid model appeared less stable than DeiT under corruption — the exact opposite of what the accuracy results (Chapter 33) predicted. This was a genuinely alarming contradiction: either the accuracy-based theory was wrong, or something about the drift measurement itself was invalid.

Diagnosing it — why a "fair-looking" measurement was actually unfair

Recall from Chapter 14 and Chapter 34: DeiT's classifier reads only the CLS token — it never looks at the patch tokens directly at all. Probing "a fixed mid-network layer's patch tokens" for DeiT was therefore measuring the stability of a representation DeiT's own classifier never actually uses to make its decision. Whatever that patch-token representation was doing under corruption — stable or unstable — was simply irrelevant to how DeiT actually classifies, because DeiT throws that information away and reads CLS instead. Meanwhile Swin and both NCA models genuinely do classify from (a pooled version of) patch tokens — so the "same" measurement was measuring something meaningful for three of the five models and something structurally irrelevant for the other two, while presenting all five numbers side by side as if they were comparable.

The fix: instead of one fixed layer for every model, hook each model's own actual pre-head input — whatever specific vector its own classifier genuinely reads, per Chapter 34's table (CLS for ViT/DeiT, GAP'd patch tokens for Swin and both NCA variants). This single change reversed the conclusion, back into agreement with the accuracy-based prediction: the Hybrid model's real classifier input is measurably more stable than DeiT's, on 17 of 19 corruptions.

Key Insight — why this is worth including at all, rather than quietly fixing it and moving on

A methodologically invalid measurement can still produce a clean, confident, precisely-numbered, entirely wrong result — there was nothing statistically noisy or ambiguous about the first (incorrect) version; it was simply measuring the wrong thing, consistently. Catching this required understanding what the metric was supposed to represent — "the input the classifier actually reads" — not just computing a number correctly in isolation and checking it against a sanity threshold. This case study is included explicitly, by name, in both the paper and this book, rather than silently corrected, because a mentor or reviewer who understands this failure mode will trust the final, corrected result more, not less — and because it's a genuinely useful, transferable lesson about representation-level analysis in any Vision Transformer variant with a nonstandard classification head, not just this project's specific models.

Chapter 36 · Part VIII

Grad-CAM: Seeing What the Network Looks At

Intuition

Every result so far has been a number. Grad-CAM (Gradient-weighted Class Activation Mapping) produces something you can look at directly: a heatmap over the input image, highlighting which regions most influenced the network's prediction for a specific class — a visual sanity check that the network is basing its decision on the object itself, rather than some unrelated shortcut like background texture.

How it's computed

For a chosen convolutional feature map A (a grid of channel activations partway through the network) and a target class score yc, Grad-CAM computes the gradient of the class score with respect to that feature map — exactly Chapter 3's gradient machinery, applied to an internal feature map instead of a weight — and averages it spatially, per channel, to get one importance weight αk per channel k:

αkc = GlobalAveragePool( ∂yc / ∂Ak )

The heatmap is then a weighted sum of the feature map's channels, using these importance weights, passed through ReLU (Chapter 7) to discard any channel that pushed the score down and keep only the ones that pushed it up in support of the target class:

LGrad-CAMc = ReLU( Σk αkc Ak )
How the examples were chosen — avoiding cherry-picking

It would be easy, and misleading, to scroll through images by eye until three "nice-looking" examples turn up. Instead, the selection criterion was fixed in advance and applied mechanically: search all 600 relevant test images for the cases with the highest agreement among the four baseline models on the wrong answer, specifically where the Hybrid model gets it right. This is a search over a stated, fixed criterion applied to the whole set, not a visual pick — the same distinction Chapter 33 draws between a single "robustness score" and a decomposed, falsifiable claim: a rule stated and applied consistently is trustworthy in a way that "we looked until we found a good one" is not.

Chapter 37 · Part VIII

Real-World Validation: BUSI Breast Ultrasound

Intuition

Every result so far uses a synthetic corruption benchmark (Chapter 33) — noise added by software to an otherwise-clean photograph. This chapter tests the theory's prediction on a domain where the "noise" is not synthetic at all: it's a physical, unavoidable property of how the imaging device works.

Why ultrasound, specifically

Speckle is a granular, high-frequency interference pattern that appears in any imaging modality using coherent waves — ultrasound reflects sound waves off tissue, and where many reflected wavefronts overlap, they interfere constructively and destructively, producing a grainy texture layered on top of the real anatomical structure. It is not sensor malfunction or a processing artifact; it is intrinsic to the physics of the imaging method itself, present in essentially every clinical ultrasound image. Chapter 33's frequency-family breakdown found speckle_noise specifically responsible for the single largest per-corruption advantage measured anywhere in the whole CIFAR-100-C sweep (+9.6 percentage points, within the +8.3pp additive-noise family average) — making ultrasound a domain where the theory makes a strong, specific, checkable prediction, rather than a generic "let's also try a medical dataset."

The dataset used is BUSI (Al-Dhabyani et al., 2020): 780 breast ultrasound images from 600 patients, labeled into 3 classes — 437 benign, 210 malignant, 133 normal — trained completely from scratch (Chapter 10), with no pretraining, at the same underlying recipe used everywhere else in this project.

Why plain accuracy is the wrong metric here

Worked Example — why 56.1% top-1 accuracy can mean nothing at all

437 of 780 images (56.1%) are the "benign" class. A classifier that always outputs "benign," regardless of the input — a model that has learned literally nothing about the images — scores 56.1% top-1 accuracy purely by exploiting the class imbalance. Any accuracy number below roughly 56% would actually be informative (worse than doing nothing), but a number comfortably above 56% could still just mean "leans benign a bit more often than chance," not "learned to distinguish the classes."

Two metrics that don't have this blind spot: balanced accuracy (the average of each class's own recall, so every class counts equally regardless of how many examples it has) and macro-F1 (the average of each class's own F1 score — itself a balance of precision and recall for that class).

Worked Example — balanced accuracy and macro-F1, from a toy confusion matrix

A small, invented 3-class confusion matrix (rows = true class, columns = predicted class, 30 toy test images total, mirroring BUSI's imbalance):

True \ PredBenignMalignantNormalTotal
Benign (17)133117
Malignant (8)2518
Normal (5)2035

Recall per class (correct predictions ÷ true total for that class): Benign 13/17=0.765; Malignant 5/8=0.625; Normal 3/5=0.600.

Balanced accuracy = mean of the three recalls = (0.765+0.625+0.600)/3 = 0.663 (66.3%) — notice this treats the 5-image Normal class as equally important as the 17-image Benign class, unlike plain accuracy, which would let Benign's larger count dominate the average.

Precision per class (correct predictions ÷ total predicted as that class): Benign 13/(13+2+2)=13/17=0.765; Malignant 5/(3+5+0)=5/8=0.625; Normal 3/(1+1+3)=3/5=0.600 (matching recall in this particular toy example only by coincidence of the numbers chosen).

F1 per class = 2×precision×recall / (precision+recall): Benign = 2×0.765×0.765/(1.53) = 0.765; similarly Malignant = 0.625, Normal = 0.600.

Macro-F1 = mean of the three F1 scores = (0.765+0.625+0.600)/3 = 0.663 (66.3%). Both metrics above are computed by averaging per-class performance after it's calculated separately per class — the minority class's poor performance can't be hidden by the majority class's strong performance, the way it can be under plain top-1 accuracy.

The Mixup story (methodology case study #2)

The first run gave an ambiguous, contradictory result

Run at the CIFAR-100 recipe entirely unchanged (Mixup/CutMix on, no class weighting, Chapter 10), the Hybrid model won on top-1 accuracy (61.94% vs. 54.84%) but lost on balanced accuracy (40.89% vs. 47.01%) and macro-F1 (37.40% vs. 41.60%) — a genuinely confusing split verdict, not a clean win either way.

The likely cause: BUSI has only 625 training images after the split, roughly 9 batches of 64 per epoch (Chapter 10), and just 107 of those 625 are the minority "normal" class. Mixup (Chapter 10) blends pairs of images and labels together — with so few minority-class examples to begin with, a large fraction of the "normal" class's already-scarce signal gets diluted into blended, partial-credit examples before either model has enough clean repetitions to learn the class distinctly. The fix: disable Mixup and CutMix entirely for this dataset, and add inverse-frequency class-weighted cross-entropy — scaling each class's contribution to the loss (Chapter 8) up or down in inverse proportion to how common that class is in training, so the numerically rare "normal" and "malignant" classes contribute as much total learning signal as the common "benign" class, rather than being statistically drowned out by it.

The result, replicated across 3 seeds

A single favorable-looking run after a recipe change could itself just be luck. To check, both architectures were retrained at 3 independent seeds under the corrected recipe (no Mixup/CutMix, class-weighted CE).

Standard deviation measures how spread out a set of numbers is around their mean — a small std means the numbers cluster tightly; a large std means they vary a lot from run to run. Key Insight — why "no overlap" is stronger evidence than comparing means alone

The Hybrid model's worst of its 3 seeds (44.42% balanced accuracy) still beats DeiT's best of its 3 seeds (39.82%) — the same holds for macro-F1 (39.32% vs. 28.56%). This means that even granting DeiT its luckiest run and the Hybrid model its unluckiest one, there is still no overlap: across every seed actually tried, DeiT never caught up. That is meaningfully stronger evidence than "the average was higher," because it doesn't rely on trusting that the specific seeds tried were themselves perfectly representative — though with only n=3 seeds per architecture, this remains a small sample, and the paper is careful to call the result "suggestive and consistent," not a large-sample statistical guarantee.

A second, unplanned finding fell out of the reruns: DeiT's top-1 accuracy fell below the 56.13% majority-class baseline (Chapter 37's opening worked example) on all 3 seeds (32.26%, 30.32%, 28.39%) — under aggressive class-reweighting with Mixup's regularizing effect removed, DeiT appears not to be learning the task at all, while the Hybrid model remained informative throughout. Whether this instability is itself a downstream consequence of the same noise-suppression mechanism (plausible: an implicit smoothing effect could also stabilize optimization, not just resist corruption) or an unrelated finding is explicitly left as an open question rather than asserted as a proven causal claim — there is no controlled experiment in this project that isolates the two possibilities from each other.

The patient-split caveat, stated plainly

BUSI's public release provides no patient identifiers for its 600 patients. This means a train/validation split guaranteed to keep every patient entirely on one side is not constructible from the public data — images from the same patient may appear on both sides of the split used here, which can inflate absolute performance numbers for every architecture, roughly equally, since nothing about the potential leakage favors one architecture's mechanism over another's. The comparison between architectures — which is what this section's claim actually rests on — is not undermined by this. But the absolute balanced-accuracy numbers themselves should not be read as an estimate of how either model would generalize to a genuinely new, unseen patient; that would require a dataset release with patient-level identifiers, which this one does not provide.

Honest Limitations

Intuition

A results section that never mentions a weakness is less trustworthy than one that does — every limitation below appears explicitly in the paper's own Discussion section, stated as plainly as any of the positive results.

  • Speed. Throughput is roughly 3× lower than DeiT-Tiny, FLOPs about 2.2× higher (Chapter 25). The underlying complexity argument (linear vs. quadratic in token count) is theoretically sound, but no fused GPU kernel exists yet for the K-iteration loop, so the practical speed advantage the theory predicts hasn't been realized in this implementation.
  • Single-seed headline numbers. Table 1's main CIFAR-100 accuracy figures (Chapter 30) are reported at a single seed (42). The depth-ordering ablation (Chapter 31) and the BUSI validation (Chapter 37) additionally cover seeds 123 and 7, but full multi-seed variance for the headline clean-accuracy comparison itself is not yet available.
  • A stratified corruption subset, not the full benchmark. Chapter 33's evaluation uses 1000 images per (corruption, severity) cell at 3 of CIFAR-100-C's 5 severities, chosen to keep a 19-type × 5-architecture sweep tractable on a single workstation GPU — not the full 950,000-image grid. There's no specific reason to expect the pattern to change on the full grid, but this has not been verified.
  • BUSI's patient-split caveat (Chapter 37): absolute balanced-accuracy numbers should not be read as clean-generalization estimates; the architecture comparison is the part that holds.
  • The impulse-noise failure is real, not an edge case to explain away (Chapters 33–34): any deployment where salt-and-pepper-style sensor faults dominate should not expect this architecture to help, and should expect it might actively hurt.
  • Scale. Everything in this project is CIFAR-100-scale data and tiny-scale models (5–8M parameters, Chapter 27's table). ImageNet-1k and larger-scale behavior are untested.
Key Insight

Similarly, the paper is explicit that the corruption-robustness and BUSI results are offered as an architectural property with a candidate downstream application — not a validated clinical claim. Section 5.7 of the paper is a controlled architecture comparison on a public benchmark dataset, not a diagnostic accuracy claim, and should never be represented as evidence of clinical readiness. This distinction matters directly for Chapter 41.

Chapter 41 · Part IX

From Research to Patent, in Plain English

Intuition

A research paper and a patent application are answering different questions. The paper asks "is this true, and can it be reproduced?" A patent asks "is this a new, non-obvious, useful technical invention, described precisely enough that someone skilled in the field could build it?" This chapter explains, in plain terms, what that second question involves — and two specific legal issues flagged for the mentor's patent agent, rather than resolved here, because they are legal judgment calls, not engineering ones.

What "patentable" generally requires

Broadly, and in most jurisdictions including India: an invention must be novel (not already publicly known or published, anywhere, before the filing date), involve an inventive step (not obvious to someone already skilled in the relevant field, given what's already known), and have industrial applicability (it must actually be usable/makeable, not purely theoretical). The project's engineering work — the specific mechanism (Chapter 23), the specific design decisions and their justifications (Chapter 24), and the specific, measured technical effect (Part VIII) — is the raw material for arguing all three; whether that argument succeeds, and how it should be worded, is what a patent agent is for.

Two India-specific legal flags

Section 3(k) — mathematical methods and computer programs

India's Patents Act, Section 3(k), excludes "a mathematical method or a computer programme per se" from being treated as a patentable invention. An architecture described purely as a sequence of formulas (which is, honestly, most of what Chapter 23 is) risks being read this way. The standard path around this exclusion is to frame the invention around its concrete technical effect — a specific, measurable improvement in how a physical or technical system behaves (here: the measured corruption-robustness and representation-stability results of Part VIII) — rather than the underlying mathematics in isolation. Whether a given claim's wording achieves this framing successfully is a legal judgment call that depends on precise claim drafting, which is exactly why this is flagged for the patent agent rather than treated as already resolved.

Section 3(i) — methods of diagnosis

Section 3(i) excludes methods of diagnosis, treatment, or surgery practiced directly on the human or animal body. Because Chapter 37's validation uses a medical imaging dataset (breast ultrasound), there's a real risk of a claim being read as "a method of diagnosing breast cancer" rather than as what it actually is: a general-purpose image-classification architecture, validated in one particular application domain among others. This is exactly why the patent disclosure frames BUSI as one embodiment of a general system claim (Chapter 37's own framing throughout this book: "a controlled architecture comparison on a public benchmark dataset," never a diagnostic claim) rather than as a stand-alone diagnostic method claim — again, a claim-drafting decision for the patent agent, not something settled by the engineering alone.

Provisional vs. complete specification

A provisional specification is a shorter, earlier filing that secures a priority date (the legal "first to file" timestamp competitors are measured against) without needing every claim finalized, giving 12 months to file the full complete specification with polished, legally precise claims. This project's patent disclosure was prepared as a provisional specifically because the research is still active — more validation (larger scale, more seeds, per Chapter 40) may still change or strengthen exactly how the claims should be worded, and a provisional secures the priority date now without locking in claim language before that work is done.

Key Insight

Glossary

AdamW
The optimizer used throughout this project — Adam-style adaptive gradient descent (Chapter 9) with weight decay applied directly rather than folded into the gradient.
Adversarial example
An input deliberately, minimally altered using a network's own gradient to cause misclassification (Chapter 32).
AMP (mixed precision)
Training with most numbers in 16-bit instead of 32-bit precision, for speed and memory savings (Chapter 10).
Attention / self-attention
A mechanism where every token compares itself (via Query/Key dot products) against every other token to compute a weighted blend of their Values (Chapter 15).
Backpropagation
The algorithm that computes the loss's gradient with respect to every weight in a network, via repeated application of the chain rule (Chapter 9).
Balanced accuracy
The average of each class's own recall — unaffected by class imbalance, unlike plain accuracy (Chapter 37).
Batch size
The number of training images processed together before one weight update; 64 throughout this project (Chapter 10).
Bernoulli distribution
A random variable taking value 1 with probability p and 0 otherwise (Chapter 4); used as the stochastic update gate in Chapter 23.
Big-O notation
Shorthand for how a cost grows as an input size grows, ignoring constant factors (Chapter 5).
BUSI
Breast Ultrasound Images dataset, 780 images, 3 classes, used for real-domain validation (Chapter 37).
Chain rule
The calculus rule for differentiating a composition of functions; the mathematical basis of backpropagation (Chapter 3).
CIFAR-100 / CIFAR-100-C
The primary 100-class image dataset (Chapter 29) and its corrupted-image robustness benchmark variant (Chapter 33).
CLS token
A learned, non-spatial token prepended to the patch sequence, traditionally read for classification (Chapter 14); excluded from all NCA computation in this project (Chapter 24).
Convolution
Sliding a small kernel over a grid, computing a dot product at each position (Chapter 11).
Corruption robustness
Accuracy under non-adversarial, naturally-occurring image degradation (Chapter 33), as distinct from adversarial robustness (Chapter 32).
Cosine similarity
A dot product normalized by vector lengths, measuring pure directional similarity (Chapter 34).
Cross-entropy loss
The standard classification loss, −log of the predicted probability assigned to the correct class (Chapter 8).
Depthwise convolution
A convolution applying a separate filter to each channel independently, with no cross-channel mixing (Chapter 11).
DeiT
Data-efficient image Transformer; here, an architecture baseline trained under this project's own recipe (Chapter 18).
Derivative / gradient
The slope of a function; the gradient generalizes this to many variables at once (Chapter 3).
Drift (representation drift)
1 minus the cosine similarity between a model's clean and corrupted classifier-input feature (Chapter 34).
EMA (exponential moving average)
A slow-moving, smoothed copy of the network's weights, maintained alongside the actively-trained weights (Chapter 10).
Emergent Attention
This project's NCA-based replacement for self-attention (Chapters 22–25).
Epoch
One full pass through the entire training dataset (Chapter 10).
Falsifiability
The property of a claim that it could, in principle, have been shown wrong by evidence — the philosophical basis for Chapter 34's drift falsification test.
F1 score / macro-F1
The harmonic mean of precision and recall for one class; macro-F1 averages this across all classes equally (Chapter 37).
FGSM
Fast Gradient Sign Method; a single-step adversarial attack (Chapter 32).
FLOP / GFLOP
One floating-point operation (an add or multiply); a GFLOP is one billion of them (Chapter 30).
Grad-CAM
A technique for visualizing which image regions most influenced a network's prediction (Chapter 36).
Hybrid NCA-ViT
This project's main architecture: 6 Emergent Attention blocks followed by 6 standard attention blocks (Chapter 26).
Kernel (convolution filter)
A small grid of fixed numbers used to compute a convolution, e.g. a Sobel filter (Chapters 11–12).
Label smoothing
Softening a classification target away from exact 0/1 values, to discourage overconfidence (Chapter 8).
LayerNorm
Normalizing each token's vector to zero mean and unit variance before rescaling (Chapter 16).
Learning rate
The step size used in gradient descent (Chapter 9); this project uses a cosine schedule with warmup (Chapter 10).
Linear layer
A matrix multiplication plus a bias vector; the basic building block of every neural network layer (Chapter 2).
Matrix / matrix multiplication
A rectangular grid of numbers, and the operation of combining two such grids via repeated dot products (Chapter 2).
MHSA
Multi-head self-attention; several attention computations run in parallel on separate slices of the embedding dimension (Chapter 16).
Mixup / CutMix
Data augmentation techniques that blend pairs of training images and labels together (Chapter 10); deliberately disabled for BUSI (Chapter 37).
MLP (multi-layer perceptron)
A small stack of linear layers with activation functions between them (Chapter 6).
NCA (Neural Cellular Automaton)
A learned, local, iterated update rule applied identically across every cell of a grid (Chapter 20).
Overfitting
When a network specializes to its training data at the expense of generalizing to new data (Chapter 10).
Parameters
The individual trainable numbers (weights and biases) inside a network's matrices (Chapter 28).
Patch embedding
The linear layer that converts a flattened image patch into a token vector (Chapter 14).
PGD
Projected Gradient Descent; a strong, iterative, worst-case adversarial attack (Chapter 32).
Position embedding
A learned vector, added per patch position, giving the network access to spatial order (Chapter 14).
Precision / Recall
Precision: of everything predicted as class X, what fraction was correct. Recall: of everything actually class X, what fraction was correctly found (Chapter 37).
Provisional specification
An early patent filing that secures a priority date ahead of a full complete specification (Chapter 41).
Random seed
The starting number that fully determines a run's sequence of "random" choices, making training reproducible (Chapter 10).
RandAugment / Random Erasing
Data augmentation techniques applying randomized image transforms or occlusions during training (Chapter 10).
Receptive field
The region of the input that can possibly influence a given output position (Chapter 13).
ReLU
Rectified Linear Unit; the activation function max(0, x) (Chapter 7).
Residual connection
Adding a sub-layer's output to its own input, rather than replacing it (Chapter 16).
Sobel filter
A classical, fixed 3×3 kernel approximating a directional brightness gradient (Chapter 12).
Softmax
A function turning a vector of arbitrary scores into a valid probability distribution (Chapter 7).
Standard deviation
A measure of how spread out a set of numbers is around their mean (Chapter 37).
Stochastic gate
The Bernoulli-distributed coin flip deciding whether a given cell's update is applied at a given step (Chapter 23).
Swin Transformer
A Vision Transformer using windowed local attention and hierarchical downsampling (Chapter 18).
Token
One element of the sequence a Transformer processes — one image patch, in this project (Chapter 14).
Top-1 / Top-5 accuracy
Whether the correct class is the single top prediction, or anywhere in the top 5 (Chapter 29).
Vector
An ordered list of numbers (Chapter 1).
ViT (Vision Transformer)
The original patch-based, pure-attention image classification architecture (Chapter 18).
Weight decay
A constant pull of every weight toward zero during training, discouraging unnecessarily large weights (Chapter 9).
Zero-initialization
Setting a layer's weights to exactly zero at the start of training, so the layer begins as an identity map (Chapter 24).
